# Practice 06 - Screens That Lead to Screens

A single Flutter application implementing all five laboratory levels with
Material Design, named routes, typed navigation results, and `PopScope`.

## Run

From this directory, run:

```sh
flutter pub get
flutter run
```

Select an Android device/emulator or Chrome. Android, iOS, and web project
scaffolding is included; building for iOS requires macOS with Xcode.

## How it works

- **Students:** the eight supplied students appear in `ListView.builder`.
  The original list and its scroll position stay intact while visiting details.
- **Details:** group and email appear with their required icons. Edit opens a
  named route and awaits a `String` result. Saving changes only the name in this
  detail screen; the original constant student list stays unchanged.
- **Edit:** the field starts empty as required by the lab, while the draft
  starts with the current name. Saving without typing returns the current name.
  Back immediately closes an unchanged draft. A changed draft prompts
  **Discard changes?**, with **Keep editing** and **Discard** actions.
- AppBar back arrows are generated by Flutter. AppBar and system Back use the
  same `PopScope` check. Explicit Save and confirmed Discard use `Navigator.pop`;
  successful pops are ignored by the confirmation callback. A pending-dialog
  guard prevents duplicate confirmations.

Route constants and the route factory live in `lib/routes.dart`; `main.dart`
configures the application in fewer than 40 lines. Screens receive a `Student`
through constructors and do not import their destination screens.

## Required screenshots

Both files are included in this project root, captured from the actual web app
running in headless Chrome. To replace them with Android captures:

1. `screenshot_detail.png`: open Aida, tap Edit, enter **Aida Updated**, then
   Save. Capture the detail screen with the updated title, group, and email.
2. `screenshot_dialog.png`: tap Edit again, enter a different name, then press
   the AppBar Back arrow. Capture the **Discard changes?** dialog.

To capture on Android, use the emulator's screenshot button and save/copy the
result under the required filename. Alternatively, replace `adb` with the full
path to your Android SDK's `platform-tools/adb` and run these commands from this
directory while each required screen is visible:

```sh
adb shell screencap -p /sdcard/screenshot_detail.png
adb pull /sdcard/screenshot_detail.png screenshot_detail.png
adb shell screencap -p /sdcard/screenshot_dialog.png
adb pull /sdcard/screenshot_dialog.png screenshot_dialog.png
```
